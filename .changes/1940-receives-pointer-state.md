### Added

- **`@reticlehq/core`, `@reticlehq/browser`, `@reticlehq/engine`: a new element state, `receivesPointer`, asks whether a tap at the element's centre reaches it.** `visible` means rendered and in layout. A fixed modal header over a mobile close button leaves the button `visible` and untappable. `receivesPointer` is true when the element is visible, is in the viewport, and no app element is on top of it at its hit points. The element, an ancestor or a descendant on top still counts as reached. It uses the same hit-test that `act` reports `occluded` from, so Reticle's own UI never counts as a cover. An element with no layout box is judged by `visible` alone. A page whose SDK is older than 3.10.0 cannot answer the state, so a check on it is inconclusive instead of a false pass.
