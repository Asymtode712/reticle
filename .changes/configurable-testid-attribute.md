### Added

- **`@reticlehq/browser`, `@reticlehq/vite-plugin`: a project can name its test-id attribute.** `{ testid: "x" }` only read `data-testid`, so Elastic UI (`data-test-subj`) and Cypress-style (`data-cy`) apps got "matched no element" on a control that was on screen. Set `"testIdAttribute": "data-test-subj"` in `.reticle.json` (or `testIdAttribute` on `reticle()` / `connect()`) and the locator, the advertised testids and recorded anchors all use it. When a testid query misses and the value is present under `data-test-subj`, `data-cy`, `data-test`, `data-qa` or `data-e2e`, the empty-result hint now names that attribute in `testidFoundUnder`. The default is unchanged. The `.reticle.json` key reaches the SDK through the Vite plugin only; Next.js and other setups pass `testIdAttribute` to `connect()` directly.
