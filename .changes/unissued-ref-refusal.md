### Fixed

- **`@reticlehq/server`: a `ref` Reticle never issued was reported as "stale", and the stale-ref recovery never mentioned `target`.** `reticle_act_and_wait { ref: "find:aria-label=Open menu" }` was refused with "that ref is stale: refs are invalidated whenever the DOM re-renders". That string was never a ref, so the explanation was wrong and the agent retried the same mistake. The act tools (`reticle_act`, `reticle_act_and_wait`, `reticle_act { steps }`) now refuse a `ref` without the minted `e12` shape before asking the page anything: "… is not a ref Reticle issued; refs look like e12. To address an element by its label, pass target: { label }, { role, name } or { text }." It is classified as a malformed call, not as a page that moved. The stale-ref recovery for a real `eN` now also says that on a page that keeps re-rendering, `target` resolves at action time and has nothing to go stale. A genuinely stale `eN` is still refused rather than silently re-resolved.
